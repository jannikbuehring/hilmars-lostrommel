# Architecture

Technical reference for the **hilmars-lostrommel** codebase. This document complements `output/output_explainer.md` (authoritative CSV column reference) and `open_questions.md` (original German design notes for the bracket rules).

Generated from a full read of every module in `models/`, `data_io/`, `misc/`, `checks/`, `draw/`, `viewer/`, `tests/`, plus the config and sample data files, as of 2026-07-24.

## 1. Overview

A CLI tool that generates round-robin **group draws** and single-elimination **knock-out brackets** (main + consolation) for table-tennis tournaments, across singles/doubles/mixed competitions and multiple classes (M1/M2/M3, W1/W2/W3, X1/X2/X3, etc.). Input is CSV; output is one combined CSV plus a self-contained HTML file per bracket, and results are browsed through an interactive console menu.

- **Entry point:** `hilmars_lostrommel.py` → `misc.initializer.initialize_data()` (runs the whole read → validate → draw → export pipeline once) → `misc.menu.show_main_menu()` (interactive loop to browse the results).
- **Version:** `misc/version.py` (`APP_NAME`, `__version__`) is the single source of truth. Both the startup banner (`misc/startup_info.py`, which pads the version into its fixed-width ASCII box) and the HTML bracket export read it, so the displayed version can never drift between the two. There is no `pyproject.toml`/`setup.py`, and no git tags — bump the constant.
- **Distribution:** packaged as a single console executable via PyInstaller (`hilmars_lostrommel.spec`); build artifacts land in `build/`, `dist/`, `builds/`.
- **No GUI, no network I/O.** Everything is local files + a terminal UI (`tabulate` for tables, `inquirer` for menus, `yaspin` for progress spinners).

## 2. Data flow / pipeline

`misc/initializer.py::initialize_data()` runs 8 stages in order, each wrapped in try/except with a `yaspin` spinner:

1. **Read players** — `data_io.input_reader.read_players()`. Aborts the whole run on `FileNotFoundError` or any exception.
2. **Read draw data** — `data_io.input_reader.read_draw_data()`, then split into 9 buckets: `{singles, doubles, mixed} × {all, group_stage (group_pos is None), bracket_stage (group_pos is not None)}`.
3. **Validity checks** (`checks/validity_checker.py`):
   - `check_all_players_only_exist_once()` — abort on duplicate start numbers. Also populates the `players_by_start_number` registry (see [§3](#3-core-data-model-models)).
   - `find_missing_players(draw_data)` — abort if draw data references an unknown player.
   - `find_players_not_in_draw_data(draw_data)` — warn-only.
   - `find_players_in_wrong_competition(draw_data)` — abort if a player is entered in a competition of the other gender (class code contains `W` / `M`; mixed classes `X*` are covered by the next check).
   - `find_draw_data_errors(draw_data)` — abort on any structural problem in the draw data. It concatenates the messages of seven sub-checks, each returning `list[str]`:
     - `find_invalid_round_flags` — a bracket row (`group_pos` set) must have exactly one of `main_round`/`consolation_round`; a group-stage row must have neither. Otherwise a player lands in both brackets or in none.
     - `find_group_no_pos_mismatch` — `group_no` and `group_pos` set together or both blank. Otherwise a `group_no`-only row silently becomes a group-stage row.
     - `find_duplicate_players_in_class` — a start number (A or B) appears at most once per `(competition, class, stage)`.
     - `find_duplicate_group_positions` — `group_pos` unique per `(competition, class, group_no)`. A duplicate would draw e.g. `g1p2` vs `g1p2`.
     - `find_invalid_pairs` — D/M rows need `start_number_b`, S rows must not have one, and `a != b`. A doubles row without a partner would otherwise be drawn as a singles entry.
     - `find_invalid_mixed_pairs` — every `M` pair is one `M` and one `F` player. Reads `players_by_start_number`, so it relies on the two checks above having passed.
     - `find_inconsistent_group_counts` — all group-stage rows of a class carry the same non-empty `#groups`, because stage 4 only reads `class_subset[0].amount_of_groups`.
4. **Draw groups** — for each competition_class within group-stage data (separately for S/D/M), calls `draw.group_drawer.draw_groups_monte_carlo`. Each call is timed with `time.perf_counter()` and the elapsed value stored as `draw_seconds` alongside `group`/`snapshots` in the per-class dict, which is what carries it through to the HTML export (the bracket side does the same, from inside `draw_bracket_with_snapshot_fallback`).
5. **Validate group draws** — runs `check_country_distribution`, `check_base_uniqueness`, `check_team_country_distribution` (D/M only), `get_qttr_violations` (S only) from `checks/group_checker.py`. Violations are printed and warned, never abort.
6. **Draw brackets** — for each competition_class, splits bracket-stage data into `main_round_participants` / `consolation_round_participants`, calls `draw.bracket_drawer.draw_bracket` through a local wrapper `draw_bracket_with_snapshot_fallback`, which catches exceptions, records the failure (message + snapshots) in a `bracket_failures` list, logs it, and substitutes an empty bracket — **so one class's bracket failing does not abort the run**, unlike group-draw or validity failures. The wrapper is also the single choke point where every bracket in the app is drawn, so it times each draw with `time.perf_counter()` and returns `(matches, snapshots, elapsed_seconds)` — on the failure path too. The elapsed value is stored as `draw_seconds` alongside `matches`/`snapshots` in the per-class bracket dict, which is what carries it through to the HTML export (including the viewer's on-demand re-export, which slices the same dict).
7. **Prepare export** — `data_io.output_writer.prepare_export_from_group_draw` / `prepare_export_from_bracket_draw` flatten the internal dict structures into export rows, accumulated in a local `export_data` list. The group side emits **one row per group member**; the bracket side emits **one row per bracket slot** (not per match), because `draw_number` is the *Rasterzahl* of the KO field — see [§4](#4-inputoutput-formats-data_io). `_iter_bracket_slots` is the inverse of `bracket_drawer.slot_to_match` (`slot = 2 * match_index - 1 + side`) and tolerates the short/`None`-padded match lists `slots_to_matches` produces for partially drawn brackets, the same way `bracket_html_exporter._serialize_matches` does. A bracket whose draw failed has `matches == {}` and is skipped, so one failed class does not lose the rest of the file.
8. **Write CSV** — `data_io.output_writer.write_to_csv` writes the combined `output.csv` and returns its path (reported in the spinner). It `os.makedirs` the parent directory first, mirroring `export_bracket_html`.
9. **Export groups and brackets to HTML** — for every drawn competition class (S/D/M), calls `viewer.group_html_exporter.export_group_html` (one `.html` per class, to `output/groups/`) and `viewer.bracket_html_exporter.export_bracket_html` (one `.html` per bracket type, main/consolation, to `output/brackets/`). These pre-exported files back both viewers' "View HTML" actions (see [§7](#7-viewer--cli-ux-viewer-miscmenupy)). A `run_meta` dict (`version`, `total_seconds`, `generated_at`, `random_seed`) is built once at the top of this stage and shared by **both** exporters — `total_seconds` is read from `pipeline_start` *before* the export loop, so every file reports the same run duration and none include the cost of writing the HTML. The per-class `draw_seconds` from stages 4 and 6 is passed separately (the group exporter takes it as its own argument, the bracket exporter reads it out of the bracket dict).

Error-handling summary: **stages 1-4 abort the whole pipeline on failure; stage 6 isolates failures per competition class; stage 5 and `find_players_not_in_draw_data` in stage 3 only warn.**

## 3. Core data model (`models/`)

### Active classes

| Class | File | Role |
|---|---|---|
| `Player` | `models/player.py` | One competitor: `start_number, first_name, last_name, country, base, gender, qttr`. Appends itself to module-global `players_list` on construction. |
| `DrawDataRow` | `models/draw_data.py` | One line of `draw_input.csv`: doubles as a group-stage seed entry (`group_pos is None`) or a bracket-stage entry (`group_pos` set). Registers seeding into module-global `seeding_by_start_numbers` (keyed `"A"` or `"A/B"`) as a side effect of construction. |
| `Snapshot` | `models/snapshot.py` | Generic audit-trail/undo-log entry (`action, groups, index, participants, violations, violation_score, initial_groups`) appended after every meaningful mutation during group Monte Carlo and bracket construction. Powers the interactive step-through viewer and failure diagnostics (see [§5](#5-algorithms-draw) and [§7](#7-viewer--cli-ux-viewer-miscmenupy)). |

**Module-level global registries** (implicit registry/singleton pattern — import/call order matters):
- `players_list`, `players_by_start_number` (`models/player.py`) — the latter is only populated by `checks.validity_checker.check_all_players_only_exist_once()`, *not* by `Player.__init__`. Anything that reads `players_by_start_number` (e.g. `DrawDataRow.__repr__`, the checkers, `output_writer`) requires that function to have run first.
- `seeding_by_start_numbers` (`models/draw_data.py`) — read later by `draw.bracket_drawer` to re-attach seeding to bracket-stage rows (whose CSV line has no seeding value; seeding is only given once, on the group-stage row).

**Actual runtime data shapes** (not the classes below):
- Groups = `dict[group_no, list[DrawDataRow | EmptySlot]]` (`EmptySlot` is a local placeholder class in `draw/group_drawer.py`, stripped before returning).
- Brackets = `dict[draw_number, [DrawDataRow_or_"BYE", DrawDataRow_or_"BYE"]]`.

## 4. Input/output formats (`data_io/`)

Both readers in `data_io/input_reader.py` expect **semicolon-delimited** UTF-8 CSV, header line skipped, fields split positionally (no `csv` module / DictReader used for input).

- **`players.csv`** — positional fields: `start_number, last_name, first_name, country, base, gender, qttr`. Sample header (`input/players_2026_test.csv`, UTF-8 BOM): `Startnumber;Last_name;First_name;Country;PPP_chapter;Gender;QTTR`, e.g. `1001;Wang;Chuqin;CHN;China;M;2796`.
- **`draw_input.csv`** — positional fields: `competition, competition_class, amount_of_groups, seeding, group_no, group_pos, main_round, consolation_round, start_number_a, start_number_b`. Sample header (`input/draw_input_2026_20260626_test.csv`): `S_D_M;class;#groups;seeding;group_no;group_pos;for_main_round;for_consolation;startnumber_A;startnumber_B`. `main_round`/`consolation_round` are parsed via a `_parse_bool` helper (`value.strip() == "1"`); any other value (including `"0"` or blank) is `False`. Both readers strip surrounding whitespace from **every** field, in `draw_input.csv` and `players.csv` alike, so `"GER "` does not become a separate country and `"F "` does not fail the gender check. Structural rules enforced by `find_draw_data_errors` (see [§2](#2-data-flow--pipeline) stage 3): a row with `group_pos` is flagged for exactly one bracket, a row without is flagged for none; `group_no`/`group_pos` come as a pair; D/M rows need `startnumber_B`, S rows must leave it blank; one `#groups` value per class.
- **`output.csv`** — written by `write_to_csv` with the fixed header `S_D_M, class, seeding, group_no, group_pos, for_main_round, for_consolation, draw_number, startnumber_A, last_name_A, country_A, PPP_chapter_A, startnumber_B, last_name_B, country_B, PPP_chapter_B, is_bye` (module constant `HEADERS`), semicolon-delimited, encoded **`utf-8-sig`** so the German names survive a double-click into Excel — matching the BOM the input files carry. Column semantics are documented authoritatively (in German) in `output/output_explainer.md`; three points that the format hinges on:
  - **`draw_number` is a bracket *slot*, not a match** — the Rasterzahl of the KO field, running `1..bracket_size` in ascending order (a 16-slot field is 1..16). Group rows leave it empty.
  - **`startnumber_B`/`last_name_B`/`country_B`/`PPP_chapter_B` are the doubles/mixed *partner*** of the same participant, never the opponent. In singles they are blank. Both prepare functions fill all eight A/B columns through the shared `_set_pair_fields`, which resolves names via `players_by_start_number.get` and degrades unknown start numbers to `''` rather than raising.
  - **`is_bye`** is `True` for a slot occupied by a `"BYE"` — such a row keeps only `S_D_M`, `class`, the round flags and `draw_number`; the eight player columns plus `seeding`/`group_no`/`group_pos` are blank. It is `False` on a real bracket slot and blank on a group row, where the notion does not apply. (This is the one deliberate divergence from `output_explainer.md`, which instead proposes the literal string `"bye"` in `startnumber_A`.)
- The per-class files under `output/` (`S_M1_groups.csv`, `S_M1_main.csv`, `S_M1_consolation.csv`, `example_output.csv`) are **reference/example outputs**, not something the current `output_writer.py` produces — it only ever writes one combined `output.csv`.

## 5. Algorithms (`draw/`)

### Group draw — `draw/group_drawer.py::draw_groups_monte_carlo(class_subset, amount_of_groups)`

**This is a Monte-Carlo / simulated-annealing-style local search, not backtracking** (correcting `README.md`'s claim).

1. Read tuning parameters from `config[group_draw]` (see [§8](#8-configuration)).
2. **Outer loop over `max_seed_retries` random seeds**: each attempt reseeds `random` and runs a fresh optimization; the best (lowest violation score) result across attempts is kept, with early exit on a perfect score-0 solution.
3. **Deterministic seed placement**: `class_subset` sorted by `seeding` descending, split into batches of size `amount_of_groups`, distributed round-robin (batch `j` → `group_no = j+1`) — a standard "snake" seeding so seed 1..N lands one-per-group in order. Groups are padded to `ceil(n / amount_of_groups)` with `EmptySlot` placeholders.
4. **Violation scoring** (`checks/group_checker.py`, weighted sum, lower is better):
   - `check_country_distribution` — always; max/min country-count spread across groups must be ≤1 (singles) / ≤2 (doubles/mixed).
   - `check_base_uniqueness` — always; no two participants sharing a training base ("base"/club) in the same group.
   - `get_qttr_violations` — singles only; unrated (no-QTTR) players spread evenly (max ≤ min+1).
   - `check_team_country_distribution` — doubles/mixed only; full-country and half-country teams spread evenly (max ≤ min+1) per country.
5. **Swap loop** (`max_iterations`, default 20000): picks a random non-first batch (batch 0, the highest seeds, is never touched — it stays exactly as placed in step 3), swaps two groups' occupants at that batch index, rescoring:
   - Improvement → keep, reset stagnation counters, break early on score 0.
   - Equal → keep (sideways move).
   - Worse → normally revert; but once stuck for `max_no_improvement_iterations` with escape budget remaining (`max_escape_attempts`), accept the bad swap anyway as a perturbation to escape a local minimum.
   - Every swap/revert appends a `Snapshot(action='swap'|'revert', ...)`.
6. `EmptySlot`s are stripped before returning `(best_groups, best_snapshots)`. If no perfect solution is found after all seed retries, a warning is printed.

### Bracket draw — `draw/bracket_drawer.py::draw_bracket(class_subset)`

A phased pipeline; the top-seed phase count is capped by `config[bracket_draw].max_draw_phase` (see [§8](#8-configuration) — set to `2` in the live config; only `max_draw_phase <= 1` short-circuits, returning after Phase 1).

1. **Phase 1 — place group-winners (`group_pos == top`)**, using `bye_hierarchy(num_slots)` (the classic power-of-two seeded-slot subdivision order; for a 16-slot bracket the batches are `[1] [16] [8,9] [4,5,12,13] [2,3,6,7,10,11,14,15]`). Batch 0 (slot 1) and batch 1 (last slot) are placed deterministically (seed #1, #2); every later batch is assigned **jointly** by the shared **`place_batch`** helper — the whole batch in one optimisation rather than player by player, so an early player's locally-best slot can no longer force a worse assignment on the rest. A candidate assignment is scored by simulating the sequential commit and summing the per-step `placement_penalty` (heavy penalties for unbalancing top-seed density across quarters/halves), then scoring the finished batch once with `score_bracket`. Because the player-by-player result is itself one assignment in that search space and scores identically, the joint search can only match or beat it. A batch is solved **exactly** when its assignment count `P(pool, batch)` fits `config[bracket_draw].joint_batch_max_evaluations` (default 5000 — covers every batch of a typical 16/32-slot draw); above that a hill-climb seeded with the player-by-player result runs for that many random swap/move iterations. `place_bye_greedy` remains as a one-participant wrapper. The half-level penalty balances a **net load** per half, not the raw top count: because a group winner forces its 2nd/3rd (delta 1/2) into the *opposite* half and its 4th (delta 3) into the *same* half, each winner's pressure on its own half is `top_reverse_weight(group) = d12 − d3 − 1` (= 1 for a full group with a 2nd+3rd, 0 for an uneven group missing its 3rd), while a bye consumes a slot with no opposite demand and subtracts 1. So the balanced quantity is `Σ top_reverse_weight(winners in half) − byes_in_half`, which collapses to `tops − byes` when every group is symmetric. Balancing raw winners alone treated a 3-2 and a 2-3 half split as equal even when one is un-fillable given where the bye sits (and over-weighted uneven groups), which forced needless `quarter_capacity_degrade` fallbacks. Both terms use an "allow up to 1 ahead of the other side" shape, so an odd count stays penalty-free. They stay **per-step** because they gate whether the *rest* of the draw can still be filled, so they must be charged as the capacity is consumed. Three further objectives are added by **`assignment_quality_cost`**, evaluated **once on the finished trial state**: unlike the two above these only *grade* the result, and measuring the result directly is both exact and cheaper than accumulating a per-step marginal (which is at best a lower bound on it). They are **`bye_half`**, **`tier_quarter_excess`** and **`score_round_two`** (see below).

**`bye_half`** balances the byes across the halves on their own (`open_questions.md`: "Freilose … gleichmäßig auf die Hälften verteilen"), which neither feasibility term can see: the net-load term is *exactly blind* to it, because a full group's winner (`top_reverse_weight` 1) placed together with its bye contributes `1 − 1 = 0`, so a half holding 4 winners + 4 byes and one holding 2 winners + 2 byes both score 0 — and the combined-quarter term is blind too, since that same split can be a perfect 4/4/4/4. That is exactly how S M1 consolation (26 players, 32 slots, 6 byes, 6 full groups + 4 without a 6th) drew a 4/2 bye split in 7 of 600 sweep draws. It scores `check_bye_balance_halves` on the finished trial at `BYE_HALF_BALANCE_WEIGHT`. It was **originally a per-step term too, and that was unsound**: accumulating a marginal excess on the running prefix only ever proved the *sufficient* direction — a final split with a gap ≥ 2 does charge at least one unit whatever the order — while the converse fails, so a perfectly legal final split was also charged whenever the iteration happened to visit one half twice in a row. In S M2 main (33 players, 64 slots) the three leftover group winners enter Phase 1's last batch with the byes at 4/4, so *every* assignment ends 6/5 — clean — yet the orders `h0,h1,*` and `h1,h0,*` scored 0 while `h0,h0,h1` scored 5000, on nothing but participant order. At 250× `country_half` that phantom cost decided the batch, and it was the sole reason two Slovenian group winners shared a half: the country-clean assignment needed both of its first two placements in the upper half. Unlike the tier term below, `bye_half` needs no "fully placed" guard — every bye is written the moment its recipient is committed (`opponent_slot`), so a partial state holds a *prefix* of the byes and never a number a later phase revises.

**`tier_quarter_excess`** balances each placement tier over the two quarters of *one half* (`check_placement_balance_quarters`). The tier term is intra-half because a 2nd/3rd's *half* is forced by its group's anchor, so only the quarter within it is a free choice — a global spread over all four quarters would charge for structure the draw is not allowed to change. It also ignores any tier not yet fully placed: in a 33-player/64-slot draw the 3rd places arrive as 9 bye recipients here and 2 residual players in Phase 2, and "repairing" the 9 chases a number Phase 2 is about to change. **Penalty ladder:** `half_excess × 100000` (net-load feasibility) > `combined_excess × 10000` (quarter tops+byes feasibility) > `bye_half × 5000` (`BYE_HALF_BALANCE_WEIGHT`) > `tier_quarter_excess × 2500` (`TIER_QUARTER_BALANCE_WEIGHT`) > `score_bracket + score_round_two` (tiebreakers). The top two ranks are accumulated per placement by `placement_penalty`; the next two are charged once on the finished assignment by `assignment_quality_cost`. The tier rank sits 2× below the bye one because the byes are both a rule *and* a feasibility input for the later fills while tier spread is quality only, and an order of magnitude above what `score_bracket` actually reaches during Phase 1/1b — **measured ceiling 250** across a full 33-player/64-slot draw (the few-thousand values only occur on a finished, *degraded* bracket, which no phase-1 candidate ever is). So neither distribution rule can be bought off with a country/matchup tiebreak, and neither can override a feasibility constraint or push a placeable layout onto the degrade path. The two `placement_penalty` multipliers, `BYE_HALF_BALANCE_WEIGHT` and `TIER_QUARTER_BALANCE_WEIGHT` are deliberately **not** config keys: their correctness is a strict-ordering proof, not a matter of taste, and a value above 5000 would silently outrank feasibility. Each group's winner slot is recorded as the "anchor" (`_update_group_top`) for later rules. **Returns early here if `max_draw_phase <= 1`.**

   **Why `check_no_first_vs_first` can never fire here** (worth knowing before tuning its weight): `bye_hierarchy` is a *perfect bipartition* of the match graph — batches `0..k-2` hold exactly `n/2` slots, the last batch holds the other `n/2`, no batch contains a mutually-opposing pair, and every slot's opponent lies on the other side of that split (verified for n = 8/16/32/64/128). So two group winners can share a match only if phase 1 reaches the **last** batch, i.e. only if `n_top > n/2`. Since every group contributes at least two qualifiers, `n_top = G ≤ N/2 ≤ n/2` — never true. Across all 30 class/round combinations of the real input, `winners ≤ n/2` holds, with `D_W3_main` (8 players, 8 slots, 4 winners) exactly on the boundary, where the `if batch_start >= n_top: break` exits before the last batch. Winners are also locked into `locked_slots` here and never moved again, so no later phase can create a 1-vs-1 either. `check_no_first_vs_first` is therefore kept as a **defensive validator** for degenerate inputs the code still accepts (short groups sending only their winner — 5 winners into an 8-slot bracket *does* reach the last batch); the rule that actually constrains a winner's opponent in practice is `check_top_easy_first_round` (see the rule table below).
2. **Phase 1b — distribute the remaining byes** (only when byes outnumber the group-winners, i.e. a near-all-bye bracket). Continues placing bye recipients in seeding order through the next positions (2nd, 3rd, …), each restricted to the quarter/half required by its group's anchor. Phase 1 breaks out of its batch loop the moment the group winners run out, so the rest of the partially-filled batch — and every later batch — is still free; Phase 1b therefore **continues down the same `bye_hierarchy`**, consuming its recipients in chunks matching those leftover batches and assigning each chunk jointly via `place_batch`, with every participant masked to the quarters `_required_quarters_for` allows (so the separation rules still bind and a chunk never holds two players of the same group, which would break the `group_opposite_quarter_used` 2nd/3rd rule). A chunk's candidate slots additionally exclude any slot whose bye-partner is already taken, since a phase-1b recipient occupies the whole match. **Chunk membership is feasibility-checked, not just seeding-ordered**: simply taking the top N by seeding can be *jointly* unassignable even when each member has a candidate slot of its own — e.g. four runners-up whose winners all sit in half 1 need half 0, but only three half-0 slots are free in the leftover batch. Each candidate is therefore admitted only while the chunk still admits a perfect matching (`_max_matching`, Kuhn's augmenting-path algorithm at module level); a rejected player stays in the queue for the next round of the same level, or the next level. Because matchable subsets form a transversal matroid, this seeding-ordered greedy yields the highest-seeded maximum-size chunk. The `while` loop then re-scans the shrunken free set, so a slot the top seeds are barred from goes to the next *eligible* seed instead of being abandoned — previously one infeasible chunk made `place_batch` return `None` and dropped the **entire** hierarchy level, pushing recipients into weaker slots while strong ones sat empty (e.g. a 64-slot draw seating its first runner-up in slot 20 while 8/24/25/41/57 stayed free). A `place_batch` failure now shrinks the chunk by its lowest seed and retries rather than skipping the level. Relatedly, `place_batch`'s hill-climb path (batches too large to enumerate exactly) falls back to `matching_seed` when the cost-greedy `greedy_assignment` strands a later player, so a solvable batch is never reported as impossible. Recipients the hierarchy cannot host fall back to the original per-participant tiers (required quarter → required half → any free slot). Placing all byes under one balanced pass keeps them ~evenly spread across quarters, which is what makes the leftover non-bye players fit. A no-op in the common case (byes ≤ winners). Note that every phase-1b participant is a bye recipient and so occupies a whole match; the hierarchy continuation therefore pins the canonical seeded *side* of the match, and its substantive gain is the batch structure that makes the joint assignment possible here too.
   **Round-two matchup quality.** With very many byes round one is almost entirely walkovers — the live S M2 main draw (33 players, 64 slots, 31 byes) plays *one* real first-round match — so every round-one matchup rule has nothing to grade and round two is the first round that decides anything. `derive_round_two_matches` builds a virtual `{r: [winner_of(2r-1), winner_of(2r)]}` dict (a side is known only when its feeder was a bye, otherwise `None`, which `_first_round_pair` already skips) and feeds it through the *existing* round-one checkers. Tier bounds must be supplied explicitly (`bracket_bounds`, taken from `class_subset`): deriving them from the round-two view mis-tiers it, and deriving them from a *partial* first round is no better, since during Phase 1 only the winners are placed and the bracket reads as `(top, top)` — switching the three-tier guard off exactly where it is needed.

3. **Phase 1c — `repair_bye_placements`**, a repair pass over everything Phase 1/1b locked in. Both distribution objectives are properties of the *finished* layout, but Phase 1/1b can only optimise one batch at a time: an uneven tier spread emerges *across* hierarchy levels (a 64-slot draw's runners-up are split between two levels, placed by different `place_batch` calls), and a chunk of ~16 participants into 16 slots is far past `joint_batch_max_evaluations`, so it falls to a hill-climb seeded by a cost-greedy pass that commits each player before its round-two opposite even exists. This pass is the only one with a global view. It swaps two **non-top bye recipients**, which is **feasibility-neutral by construction**: both slots are `(player, BYE)` matches before and after, so every per-quarter and per-half bye count is invariant, and a top-placed participant is **not a candidate at all** — neither as the mover nor as its partner, since a swap moves both — so the anchors, and with them the tops-per-quarter and net-half-load balances and Phase 2's dependence on `group_top_quarter`, are invariant here by construction. Phase 1 decides where the group winners sit and they stay put; this replaced an earlier, weaker rule that merely refused to move a winner to a *different* quarter, which still let one shift within its quarter (and required an anchor resync after every accepted swap). That is the same capacity-neutrality argument that makes `rebalance_bottom_tier_quarters` safe. Separations are a **hard gate** rather than a scored term (a swap may reduce them, never increase them): at 2500 a tier unit outweighs both split weights, so a scored gate would let the pass buy a tier repair with a separation. **Deterministic best-improvement**, consuming **no** randomness — drawing from the shared RNG stream would shift every downstream outcome, so a change in a drawn bracket would no longer be attributable to the rules rather than to the pass having run; best- rather than first-improvement because a sweep costs the same and taking the first improving swap settles for whatever trade it stumbles on. Gated on Phase 1b having run: without it every bye recipient is a winner, so the candidate set would come out empty anyway and the gate simply skips the work. Each accepted swap appends a `"bye_swap"` snapshot.

4. **Phase 2 — `assign_quarter_buckets`** for the remaining **non-bye** players: `delta = group_pos - top_group_pos` decides each one's required quarter relative to its group's anchor:
   - delta=1 (runner-up) → opposite half from the anchor.
   - delta=2 (3rd) → opposite half, but the *other* quarter than the one chosen for delta=1 (so 2nd/3rd from a group can meet no earlier than the quarterfinal). The `group_opposite_half_used` map that enforces this is **seeded from `slot_state`**, not built from the residual players alone: a group's delta=1 may have received a bye and been placed back in Phase 1b, in which case it is not among this phase's participants at all and the map would start empty — leaving the residual delta=2 to be chosen on capacity alone and land in the very quarter its runner-up already occupies. A 12-group / 36-player / 64-slot layout produced **8** such violations of a rule that "darf eigentlich nicht verletzt werden", and **0** after seeding the map.
   - delta=3 (4th) → same half as the anchor, different quarter (so 1st/4th can meet no earlier than the semifinal).
   - Placement order matters: a full group's delta=1/delta=2 pair is forced to occupy *both* opposite-half quarters (one each), so those "paired" delta=1 players are committed first, then the delta=2 players, and only then the **"solo" delta=1** players — a short group whose delta=1 has no delta=2 sibling (e.g. a consolation group missing its 3rd). A solo delta=1 has a real choice, so deferring it to last lets it take whatever capacity the forced players left free; committing it greedily up front could steal the quarter a full group's delta=2 is forced into and overflow it.
   - Unconstrained players are bulk-assigned to whichever quarter has spare capacity. Ties broken by country-conflict cost (`_country_cost`). If quarter capacity can't hold the residual demand, the draw **degrades gracefully** (see below) rather than failing.
   - **No tier-balance tiebreaker here**, deliberately: extending `_best_quarter` with a same-tier count (to spread the tiers the way Phase 1/1b now does) was tried and measured on the real input — capacity almost always decides before any tiebreaker is reached, so the tier imbalance was **unchanged** (12 units either way) while country conflicts *rose* (36 → 38 first-round, 18 → 21 quarter spread). This is why `check_placement_balance_quarters` can still report a non-zero count on a finished bracket even when Phase 1/1b/1c did everything available to them.
   - **`rebalance_bottom_tier_quarters` post-pass** — repairs the per-quarter *bottom-tier supply* that `check_top_easy_first_round` needs ("a group winner earned a BYE or a lowest-placed opponent"). Scoring alone cannot deliver that rule: the phase-5 Monte Carlo only shuffles **within** a quarter, so a non-bye winner can only be paired with a bottom-tier player that this phase already assigned to its quarter — and `assign_quarter_buckets` decides that blind to the rule, breaking the very first capacity tie on quarter *index*. For the live 10-group/32-slot layout that deterministically split the 3rd places 2/3 across the two quarters needing 3 and 2, stranding one winner per half; on the real input the rule was violated **22 times** across the singles draws before this pass and **0 times** after. The repair exchanges the quarters of a group's delta=1/delta=2 pair, which is exactly **capacity-neutral** (each quarter still receives one of the two) and leaves both in the opposite half in different quarters — so the half separation and the 2nd/3rd different-quarter rule are untouched, and only the deliberately lower-weighted country spread can shift. That is what makes it safe to repair *after* capacity is settled; a tie-break inside `_best_quarter` could not, since it would only steer the first delta=1 of each half (capacity forces the rest) and ranking it above capacity would risk the far more expensive `quarter_capacity_degrade` path. Greedy first-improving swaps, deterministic, consumes no RNG. **Limitation:** only delta=1/delta=2 pairs share a half and so can trade quarters safely; a 4-tier bracket's bottom tier is delta=3, which lives in the anchor's *own* half, so that case bails out and falls back to scoring alone (no class in the real data has 4 tiers).
4. **Phase 3** — groups remaining (non-bye, non-winner) players into per-quarter candidate pools per their Phase-2 assignment; a `"quarter_pool_size_mismatch"` here is a defensive guard (Phase 2's capacity check makes it unreachable in normal flow).
5. **Phase 5** (the code's own numbering; phases 3 and 4 above are the pool-building steps) — per-quarter Monte Carlo refinement: each quarter shuffled independently, then iteratively (holding the other 3 quarters fixed) tries up to `max_attempts` random reshuffles of one quarter's pool, keeping the best-scoring arrangement (`score_bracket`), stopping early at score 0. Note this only ever permutes players *within* one quarter, which is why any rule about **who faces whom** also needs the right players routed into that quarter by phase 2.

**Graceful degradation (`_fill_residual_soft`)**: when the residual non-bye players cannot be packed into their required quarters without overflow — a structurally tight, near-full bracket (e.g. an odd number of groups each contributing three positions into a bracket that is almost entirely byes) — the draw does **not** abort. Instead it fills every free slot via a Monte Carlo that minimises `score_bracket`, so half/quarter separation become soft (heavily weighted) goals and a best-effort bracket is always returned. A `"quarter_capacity_degrade"` snapshot marks the switch. Genuine structural failures (occupied deterministic seed slot, un-placeable byes) still raise.

Every phase transition/attempt appends a `Snapshot`. On unrecoverable failure, `raise_with_failure_snapshot` attaches a diagnostic snapshot (with a `"failure"` key: message/type/phase/locked_slots) to the raised `ValueError` as `.snapshots`/`.failure_snapshot`, consumed by `misc/initializer.py`'s fallback wrapper and inspectable via the interactive viewer.

**Rule implementation cross-reference** (source: `open_questions.md`):

## 6. Validation (`checks/`)

- **`validity_checker.py`** — pre-draw input sanity (see [§2](#2-data-flow--pipeline) stage 3): duplicate/missing/unused players, gender per competition, and the structural draw-data checks aggregated by `find_draw_data_errors` (round flags, `group_no`/`group_pos` pairing, duplicates per class and per group position, partners, mixed pair genders, `#groups` consistency). All are fatal except the unused-player warning.
- **`group_checker.py`** — `check_country_distribution`, `check_base_uniqueness`, `get_qttr_violations`, `check_team_country_distribution` (used both live during Monte Carlo scoring and again as a post-hoc report in `initializer.py`).
- **`bracket_checker.py`** — `check_half_group_separation`, `check_quarter_group_separation`, `check_no_first_vs_first`, `check_top_easy_first_round`, `check_no_bottom_vs_bottom`, `check_country_conflicts_first_round`, `check_country_balance_halves`, `check_country_balance_quarters`, `check_bye_balance_halves`, `check_placement_balance_quarters`, `check_base_conflicts_first_round`, the round-two family (`derive_round_two_matches`, `check_round_two_matchups`, `score_round_two`, `ROUND_TWO_DEFAULT_WEIGHTS`), and `score_bracket(matches, number_of_matches, weights=None)` (default weights: `quarter_split=200, half_split=150, first_vs_first=100, top_easy_opponent=70, bottom_vs_bottom=50, country_first=35, country_half=10, country_quarter=4, base_first=20`).

  **The `bounds=` keyword.** `check_no_first_vs_first`, `check_top_easy_first_round` and `check_no_bottom_vs_bottom` take an optional pre-computed `(top, bottom)`; when omitted they derive it exactly as before, so every existing call site is unchanged. It does **not** breach the "guard lives inside each checker" invariant below — the `bottom - top >= 2` test still runs inside each checker, the keyword only supplies ground truth a *partial* view cannot observe. Two callers need it: `check_round_two_matchups`, whose virtual dict holds only the participants the byes decided (a round two of winners and runners-up would conclude `bottom == runner-up` and both disable the guard *and* relabel a 1-vs-2 as clean), and `draw_bracket`, which passes `bracket_bounds` from its input `class_subset` because during Phase 1 the bracket itself holds only winners and reads as `(top, top)`. Agreement between the score and `get_bracket_violations` is preserved because both are handed the same value.

  The three **round-one matchup-quality** checks share `_bracket_position_bounds`, which derives `top = min(group_pos)` and `bottom = max(group_pos)` *relative to the bracket* (a main draw runs 1..3, a consolation 4..6) — the same relative convention as `check_no_first_vs_first`'s `bracket_top_position`. `check_top_easy_first_round` reports a top placement whose opponent is neither a BYE nor a bottom-tier player, deliberately **excluding** top-vs-top so that `check_no_first_vs_first` remains that match's sole owner instead of it being charged through two terms. `check_top_easy_first_round` and `check_no_bottom_vs_bottom` only apply when the bracket has **at least three placement tiers** (`bottom - top >= 2`), i.e. singles only: doubles and mixed have two tiers (main pos {1,2}, consolation {3,4}), where "bottom" *is* the runner-up, so the first rule would restate `check_no_first_vs_first` and the second would flag arithmetically forced pairings (D M1 main: 7 winners, 2 byes, 7 runners-up → 5 pair with winners, 2 must meet), a permanent penalty that would also defeat the `score == 0` early exits and make every doubles draw burn the full `max_attempts` in all four quarter phases. The guard lives *inside* each checker so the score and `get_bracket_violations` always agree — with one deliberate family of exceptions: **three checks are reported but never scored.** None of them can be improved by a phase that optimises `score_bracket`, so each would be a constant, and a bracket that cannot satisfy it would then never reach `score == 0`, defeating the early exits in all four phase-5 quarter loops (the same reasoning as the tier guard above). (1) `check_bye_balance_halves` — the byes are locked into `locked_slots` by Phase 1/1b and never move again; the drawer calls this checker directly from `assignment_quality_cost`, while they are still being placed. (2) `check_round_two_matchups` — every bye recipient sits opposite a `"BYE"` and every remaining free slot's partner is free too, so from Phase 2 on a placement can only leave a round-two side *un*decided, never change a decided one; the round-two pairing is therefore frozen after Phase 1b, and `score_round_two` exists for the drawer to call directly. (3) `check_placement_balance_quarters` — the phase-5 Monte Carlo only permutes players *within* one quarter, so it cannot move a tier count between quarters at all. All three are enforced where they still can be, by the drawer's Phase 1/1b/1c objective (see [§5](#5-algorithms-draw)), and surfaced through `get_bracket_violations` under the `bye_balance_halves`, `placement_balance_quarters` and `round2_*` keys. The round-two entries are spread as **flat** keys rather than one nested dict because both viewers hide an empty violation list and the HTML exporter decides that with `Array.isArray(v) ? v.length : true` — a dict would always render. `check_country_conflicts_first_round` has **no** tier guard and complements the two country *distribution* checks, which only balance counts across halves/quarters and so never object to a same-country pairing; for doubles a participant is a team carrying up to two countries, and only an overlap with the **opponent** counts (a same-country team is not a conflict).

  **Weight ladder.** Two invariants any retuning must preserve. (1) All three matchup terms sit strictly **above** every country weight — `open_questions.md`'s "1. gegen dritter oder freilos ist wichtiger als länderverteilung". This matters because the country terms are *magnitude*-based (`sum(v[3] for v in ...)`) and so accumulate, while the matchup terms are count-based: at 70, one `top_easy_opponent` violation outweighs a 3-unit `country_half` imbalance even under the live weights. (2) `2 × top_easy_opponent < min(half_split, quarter_split)` in **both** ladders (140 < 150 defaults, 140 < 200 live), so `_fill_residual_soft` — which has full permutation freedom and `score_bracket` as its only objective — can never trade away a half or quarter separation to fix a matchup ("Darf eigentlich nicht verletzt werden, country und base lieber violaten"). The binding constraint is the **default** `half_split = 150`, not the live 1000, which is what caps `top_easy_opponent` at 70. `tests/test_bracket_checker.py::test_soft_matchup_terms_never_outweigh_a_separation` asserts both invariants against the defaults *and* the parsed `config.ini`. (3) The three round-two **tier** weights (`round_two_first_vs_first = 45`, `round_two_top_easy_opponent = 42`, `round_two_bottom_vs_bottom = 38`) sit strictly **below** every round-one matchup weight and strictly **above** every country weight — a round-one pairing is real and immediate, a round-two one only conditional, but a group winner drawn against a runner-up a round later still matters more than country spread. That leaves the band **36..49**, which is the only one valid in *both* ladders, since `bottom_vs_bottom = 50` and `country_first = 35` happen to carry identical values in the defaults and in `config.ini`. `round_two_country_first = 9` is instead ranked *below* round one's country term, between `country_half` and `country_quarter` — and 9 is the only integer satisfying that in both ladders (defaults 10/4, live 20/8). `test_round_two_weights_sit_between_round_one_matchups_and_country` asserts the band against both, plus that `config.ini` has not drifted from the defaults it is checked against. `check_country_balance_quarters` mirrors the halves check one level down — per-country allowance `ceil(total / num_quarters)` (+1 for doubles), with excess explained by full-country teams forgiven, and the quarter count derived from the bracket so small brackets that only yield quarters 0/1 stay correct. It is deliberately weighted **below** `country_half`, so spreading a country across the halves outranks spreading it across the quarters. `draw_bracket` builds a `bracket_weights` dict from `config[bracket_draw]`'s `half_split_weight`/`first_vs_first_weight`/`top_easy_opponent_weight`/`bottom_vs_bottom_weight`/`country_first_weight`/`country_half_weight`/`country_quarter_weight`/`base_first_weight` (falling back to the defaults above) and passes it to every `score_bracket` call; there's still no `quarter_split_weight` config key, so that term stays fixed at 200.

## 7. Viewer / CLI UX (`viewer/`, `misc/menu.py`)

Console-only for tables/menus, via `tabulate` and `inquirer` — plus static-file exports (HTML/SVG, no server) for groups and brackets; still no GUI window and no network I/O.

- **Menu flow** (`misc/menu.py`): `show_main_menu()` → `View` → `{Players | Groups | Bracket}` → `{Singles | Doubles | Mixed}` → pick a drawn competition class → render via `viewer.group_viewer.show_groups` / `viewer.bracket_viewer.show_bracket`. Both of those then prompt `["View", "View HTML", "Back"]`; `misc/menu.py` itself knows nothing about the HTML files.
- **Display mode** is driven by `config["settings"]["mode"]` (`normal` = static table; `interactive` = step through `Snapshot`s one action at a time, with jump-to-next-improvement, jump-to-snapshot-number, and jump-to-final actions). It applies to the terminal "View" path only — the HTML pages always carry the full stepper.
- `viewer/viewer_shared.py` holds what the two viewers and the two exporters have in common: `clear_screen()` (was duplicated in both viewers), `open_in_browser(path)`, and `participant_display_fields(p, include_qttr=False)`. Keeping the last one out of `bracket_viewer.py` is what lets `bracket_viewer` import `bracket_html_exporter` at module level instead of lazily — the two used to form an import cycle around it. `include_qttr` is off by default because only the group views show QTTR, and the bracket payload repeats every participant in every snapshot, where an unused field would be paid for thousands of times.
- `viewer/group_viewer.py`'s interactive replay reconstructs group state by starting from `snapshots[0].initial_groups` and replaying `swap`/`revert` actions up to the current index, rather than storing full state per snapshot.
- **HTML export, groups** (`viewer/group_html_exporter.py::export_group_html`) writes one self-contained `.html` per competition class to `config["files"]["group_html_output_dir"]` (default `output/groups/`), named `{competition}_{competition_class}_groups.html` (via the shared `group_html_filename`/`group_html_path` helpers), and is wired into the menu exactly like the bracket one: all classes are exported up front in stage 9, so "View HTML" only opens the existing file, re-exporting on demand solely as a fallback. The page renders each group as a card, **one card per row** (never several groups side by side — vertical scrolling is preferable to columns being cut off), with one grid-template shared by the header and every slot row (`#`, `Seed`, name(s), `Country`, `Base`, `QTTR`; a team joins both players' values with `/`). Column widths are hard-coded, so the bracket page's `measureColumnWidths()` probe is unnecessary here — the roster is fixed, only *which* row a participant occupies changes, and fixed widths are what keep the column boundaries from shifting as the stepper swaps participants between slots. The two text-heavy columns (name(s) and `Base`) are `fr` tracks rather than fixed ones: an `fr` track's implicit `auto` minimum means it never shrinks below its content, so instead of the truncation the previous three-across grid produced, a very long value widens the row and the card scrolls horizontally (`.group-card { overflow-x: auto }`). Nothing is ellipsised. Heading, provenance footer and the `_participant_key` identity are imported from `bracket_html_exporter` so the two file families cannot drift.

  **The payload is delta-encoded, and this is the one real divergence from the bracket exporter.** Group snapshots *are* deltas (`draw/group_drawer.py` stores `initial_groups` once and then one swap/revert per iteration), and `max_iterations = 20000` with up to two snapshots per iteration means a single class can produce tens of thousands of them — the bracket exporter's full-state-per-snapshot approach would produce hundred-megabyte files. So the payload carries `roster` (each participant serialized exactly once), `initial` (the state the history starts from, as roster keys), and `steps` (one small object per snapshot: action, the two groups, the index, the two keys, the violation score and the violation dict). The JS keeps one live state object and applies a single step per navigation click — `applyStep` mirrors `_apply_snapshot` in the exporter, which in turn mirrors `group_viewer.display_snapshot`: a `swap` put p2 where p1 was, a `revert` put them back, and going backward is the inverse assignment. `tests/test_group_html_exporter.py` replays the payload in Python and asserts it lands exactly on the groups `draw_groups_monte_carlo` returned, which is what pins that three-way contract. Real input produces 30 KB–1.4 MB per class.

  **`EmptySlot` is filtered before `participant_display_fields`** (`_slot_key`): its `start_number_a == "EMPTY"` would otherwise render as `Unknown(EMPTY)`. All empty slots share the key `null`, which is correct — they are interchangeable, so swapping two of them is a no-op. The page renders the *padded* state (empty slots included, all groups the same height), while the drawn `groups` the CSV export sees have them stripped.

  **`max_snapshots`** (from `[group_draw] html_max_snapshots`, default 20000) caps the embedded history by collapsing the **oldest** snapshots into `initial` — replayed in Python at export time — rather than dropping the newest, so the page always still ends on the real drawn groups. `first_snapshot_index` keeps the on-page numbering absolute and drives a "history truncated" note. No class in the real input currently reaches the cap.

  The control bar, checkbox defaults (`Scroll to change` on, `Show violation details` off), keyboard arrows, yellow `changed` flash and dimmed `.export-meta` footer are all the bracket page's, so the two feel identical. Two deliberate differences: the page **opens on the final groups** (`render(last, silent)` — walking the whole history at load would otherwise flash and scroll to every slot the draw ever touched), and group cards are **not** color-coded by violation; the violation score is always shown and the per-rule breakdown stays behind the checkbox.
- `viewer/bracket_viewer.py::show_bracket()` first selects the bracket type (`main`/`consolation` — auto-picked if only one exists, otherwise prompted), then prompts `["View", "View HTML", "Back"]` scoped to that single type. "View" dispatches to the existing terminal renderers (`show_bracket_menu`/`show_bracket_tables`, unchanged): highlights the best quarter in green, falls back to plain `tabulate` format on `UnicodeEncodeError`. Participant formatting is centralized in `viewer_shared.participant_display_fields()` (structured data) with `format_participant_display()` as a thin string-formatting wrapper around it, so the terminal and HTML renderers share one source of truth.
- **HTML export, brackets** (`viewer/bracket_html_exporter.py::export_bracket_html`) writes a self-contained `.html` file per bracket type to `config["files"]["bracket_html_output_dir"]` (default `output/brackets/`), named `{competition}_{competition_class}_{bracket_type}_bracket.html` (via the shared `bracket_html_filename`/`bracket_html_path` helpers). **All** brackets — every singles/doubles/mixed class, main and consolation — are exported up front during `initializer.initialize_data()` (right after the CSV write), so files already exist before the menu opens. The **"View HTML"** menu action therefore just opens the pre-exported file for the chosen bracket type in the default browser (`webbrowser.open` on a `file://` URI), re-exporting on demand only as a fallback if the file is missing. Each file renders the **first round only**, as a Q1–Q4 quarter-grouped list (no later-round tree — `draw_bracket()` never simulates match winners), and embeds **every** recorded `Snapshot` as JSON, with an inline-JS stepper (Prev/Next/Jump-to-snapshot/Forward-to-next-improvement/Show-final) mirroring the terminal's interactive controls — fully offline, works via `file://`, no CDN/network references. Solves the terminal's scroll/cutoff problem for large brackets (64/128+ draws). Quarter membership mirrors `bracket_drawer.py::slot_quarter`. The strongest 25% of players (by `group_pos` asc, then `seeding` desc) are highlighted green, sized to **25% of bracket slots** (`len(matches) * 2 // 4`, byes included in the count) — so a 16-slot bracket always highlights its 4 strongest players regardless of bye count; byes are never in the candidate list, so if byes are numerous enough that the count exceeds the real-player total, only the real players are colored. Computed once from the final bracket and keyed by stable `start_number`-based identity (not `id()`, which is invalidated by the `copy.deepcopy` every snapshot stores). The terminal viewer (`bracket_viewer.py::_get_top_quarter_ids`) uses the same slot-based sizing. `_serialize_matches` pads every match to two slots so partial/phase-1 draws (where `slots_to_matches` leaves matches empty or length 1) render without the JS indexing past the array. The control bar opens with the human-readable class heading (`_class_display_name`, e.g. `S`/`M1`/`main` → "Singles Men 1 Main"; falls back to raw codes for unknown codes) and carries two checkboxes: **"Scroll to change"** (on by default; scrolls the first changed slot into view on each step) and **"Show violation details"** (**off** by default, so the per-rule breakdown from `get_bracket_violations()` is opt-in debug output — the `Violation score` line itself is always shown, since "Forward to next improvement" navigates by it). Neither is persisted; both reset to their markup default on reload. Toggling the violation checkbox calls `renderViolations()` alone rather than a full `render()`, so it cannot cancel the yellow `changed` flash of the step just taken. Each slot line reads `Seed: N   G: N   P: N   [country/base] First Last (start_number)`. Each metadata field is its own `.fld` span; at load `measureColumnWidths()` measures the widest value each field ever takes across the whole snapshot history (off-screen probe, so real font metrics) and pins that column's width via a `--col-*` CSS variable, so multi-digit or missing values never shift the following columns. Fields that are null everywhere (e.g. an unseeded draw) get no column at all. Below the bracket list, a dimmed `<footer class="export-meta">` carries the file's provenance — `Hilmars Lostrommel v0.9 · Singles Men 1 Main drawn in 3.42 s · total run 11.8 s · seed 789123 · generated 2026-08-02 14:31` — from the bracket's own `draw_seconds` plus the optional `run_meta` kwarg; the same values are repeated under a `meta` key in the embedded JSON, and the version also appears as `<meta name="generator">`. Every part is omitted when its value is missing, so the viewer's fallback re-export (which passes no `run_meta`) still renders a valid footer with just version and timestamp. Durations are formatted by `_format_duration` (`3.42 s` under a minute, `2 min 15.5 s` above).
- `viewer/player_viewer.py::show_players_table()` — flat player listing.
- `viewer/view_config.py` — single shared setting, `table_format = "rounded_outline"`, used by the table-based viewers.

## 8. Configuration (`config/config.ini`, `misc/config.py`)

Loaded once at startup by `misc.config.initialize_config(base_dir)`, which reads `<base_dir>/config/config.ini` into a module-level `configparser.ConfigParser()` singleton (imported as `from misc.config import config` throughout), seeds Python's global `random` module from `settings.random_seed` if set, and configures `logging.basicConfig` from `settings.log_level`.

| Section | Key | Meaning |
|---|---|---|
| `[files]` | `draw_data_path`, `players_path`, `output_file_path` | Input/output file locations. |
| | `bracket_html_output_dir` | Directory for HTML bracket exports (`viewer.bracket_html_exporter`); falls back to `output/brackets` if unset. |
| | `group_html_output_dir` | Directory for HTML group exports (`viewer.group_html_exporter`); falls back to `output/groups` if unset. |
| `[settings]` | `log_level` | 10/20/30/40/50 = debug/info/warning/error/critical. |
| | `mode` | `normal` or `interactive` (viewer step-through). |
| | `random_seed` | If set, makes random outcomes deterministic. |
| `[group_draw]` | `max_iterations`, `max_no_improvement_iterations`, `max_escape_attempts`, `max_seed_retries` | Monte Carlo tuning (see [§5](#5-algorithms-draw)). |
| | `country_violation_weight`, `team_country_violation_weight`, `base_violation_weight`, `qttr_violation_weight` | Weights for the group violation score. |
| | `html_max_snapshots` | Cap on the snapshots embedded in the group HTML export; the oldest beyond it are collapsed into the page's start state, so the final groups always survive. Falls back to 20000. |
| `[bracket_draw]` | `max_attempts` | Per-quarter Monte Carlo attempts in Phase 5. |
| | `max_draw_phase` | **1-5; how many of the 5 bracket phases to run.** |
| | `joint_batch_max_evaluations` | Evaluation budget for the joint per-batch assignment in phase 1/1b: a batch is solved exactly when its assignment count fits, otherwise a hill-climb runs for that many iterations. |
| | `half_split_weight`, `first_vs_first_weight`, `country_half_weight`, `country_quarter_weight`, `base_first_weight` | Weights for the bracket violation score (`score_bracket`); keep `country_quarter_weight` below `country_half_weight`. No `quarter_split_weight` key exists, so that term is fixed at 200. |
| | `top_easy_opponent_weight`, `bottom_vs_bottom_weight`, `country_first_weight` | Weights for the round-one matchup-quality rules. Must stay **above** all country weights, and `2 × top_easy_opponent_weight` must stay **below** `half_split_weight` and the fixed `quarter_split` of 200 — see the ladder invariants in [§6](#6-validation-checks). |

The Phase-1 structural penalties are deliberately **not** configurable — `placement_penalty`'s `100000 / 10000 / 5000` and `bracket_drawer.TIER_QUARTER_BALANCE_WEIGHT = 2500` encode a strict ordering (feasibility > explicit distribution rules > quality tiebreakers) whose correctness is a proof rather than a preference; a key set above 5000 would silently outrank feasibility and produce `quarter_capacity_degrade` fallbacks that look like drawer bugs. Phase 1c likewise has no budget key: it is a deterministic best-improvement sweep that terminates when no swap improves.

## 9. Known Issues

Concrete bugs, dead code, and config/behavior mismatches found while documenting this codebase.

- **`score_bracket`'s default weights have drifted from `config/config.ini`** — most visibly `half_split` (150 default vs `half_split_weight = 1000` live), which also inverts the intended rank of `quarter_split` (fixed at 200) against it. Nothing under `pytest` calls `misc.config.initialize_config` (only `hilmars_lostrommel.py` does), so **the test suite only ever exercises the defaults while the app only ever uses `config.ini`**. Any new weight therefore has to be sane in *both* ladders — see the invariants in [§6](#6-validation-checks). Not yet reconciled because raising the defaults to match would silently change every existing test's scoring.
- **`quarter_capacity_degrade` on the tightest layouts.** Phase 1b can leave its single free match in a quarter the two residual non-bye 3rd places cannot both use (their groups' anchors sit in *different* halves), so one of them can never be placed legally and all separations go soft. Phase 1c cannot fix it: swapping bye recipients never moves *which* match is left free. A fix would need Phase 1b to choose the free match against the residual players' required halves, or a residual-feasibility term in Phase 1c's objective. Moving the bye-half rule onto the finished state (see [§5](#5-algorithms-draw)) took the live run from four degraded brackets to two — **S M2 main and D W3 consolation no longer degrade**; S M2 consolation and S W2 consolation still do. Note that S M2 main's two `half_group_separation` violations **survived** that change, so contrary to what this entry previously claimed they are not a consequence of the degrade path.
- **`check_placement_balance_quarters` can report a non-zero count on a finished bracket even when Phase 1/1b/1c did all they could** — the tiers those phases do not place are decided by Phase 2's capacity buckets, which have no tier-balance criterion (see [§5](#5-algorithms-draw) Phase 2 for the measurement showing why adding one there makes things worse). Across the real input this is 12 units, concentrated in the small 4- and 8-match brackets where a "quarter" is one or two matches.
- **Module-level global state** (architectural limitation, not scheduled for rework): `players_list`, `players_by_start_number` (`models/player.py`), and `seeding_by_start_numbers` (`models/draw_data.py`) are singleton registries mutated as a side effect of object construction or specific function calls — see [§3](#3-core-data-model-models) for the call-order trap this creates (`players_by_start_number` stays empty until `check_all_players_only_exist_once()` runs). Similarly, `misc/initializer.py`'s per-competition result dicts (`singles_groups`, `doubles_brackets`, etc.) are populated by `initialize_data()` and then imported and read directly by `misc/menu.py`, rather than being passed as parameters — the menu module has an implicit dependency on the pipeline having already run. This pattern is pervasive enough that fixing it is a deliberate, dedicated effort rather than an opportunistic patch.

## 10. Build

Packaged via **PyInstaller** (`hilmars_lostrommel.spec`): single console executable (no windowed/GUI mode), entry point `hilmars_lostrommel.py`, `collect_all('readchar')` to bundle that package's data/binaries/hidden imports, UPX compression enabled, no code signing. Build output in `build/hilmars_lostrommel/`; distributable artifacts in `dist/` and `builds/`.

The exe reads `config/config.ini` next to itself at runtime (see `get_base_dir()` in `hilmars_lostrommel.py`), not from PyInstaller's bundled `datas` (this is a onefile build, so bundled datas only get extracted to a temp `_MEIPASS` dir, not next to the exe). Because of that, the spec file copies the live `config/` directory into `DISTPATH` after `EXE()` runs, so every build refreshes `dist/config/config.ini` from source instead of leaving a stale copy behind.
